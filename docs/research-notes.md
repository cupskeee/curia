# Curia research notes

Research dates: 2026-10-03 (game, SDL/ImGui, APIs, tools: nine tasks) and 2026-10-04 (open-source repository practice, C++ release engineering, VOTC-CE facts, Agent Mode read-only scoping: four tasks), plus read-only listings of the owner's own CK3 install and user folder (marked *observed*). Game: CK3 1.20.0.3 "Crozier" (released 2026-09-30, hotfix 2026-10-01).
Method: primary sources preferred. Runtime behaviour that research cannot settle is **not estimated**: it is listed as a spike question (section 5), each with the milestone that answers it.

Source kinds: **[official]** vendor docs / patch notes, **[source]** source code or a game-generated dump, **[wiki]** the CK3 community wiki, **[anecdotal]** forum posts, issue trackers, community repos. Anything that is only [anecdotal] is flagged in the text.

## 2. Verified facts

### 2.1 CK3 logging (`debug_log`)
- `debug_log = "message"` logs a string when the effect runs; the message may be a localization string with ROOT, SCOPE and PREV available; usable from any scope. Siblings: `debug_log_scopes`, `debug_log_date`, `debug_log_stack_trace`; `error_log*` variants write to the error log. Source: a third-party mirror of a game-generated effects dump from build 2025-11-24, **not re-verified for 1.20**; T6/T10 confirm against the owner's local dump. [source] <https://raw.githubusercontent.com/nonniks/CK3_Documentation/main/logs/effects.log>
- ck3-tiger's tables model `debug_log` as scope-agnostic free-form. [source] <https://raw.githubusercontent.com/amtep/tiger/main/src/ck3/tables/effects.rs>
- The wiki's modding guide shows bracketed scope text in the sibling `error_log = "Event fired for [ROOT.Char.GetName]"` as a documented way to export information. [wiki] <https://github.com/jesec/ck3-modding-wiki/blob/master/wiki_pages/Scripting.md>
- User-data/logs folder: Windows and macOS `Documents/Paradox Interactive/Crusader Kings III/logs/` (`error.log`, `debug.log`, `game.log`). [wiki] <https://ck3.paradoxwikis.com/Modding>. macOS corroborated by Paradox staff (path given, "logs" subfolder inferred). [anecdotal] <https://devtrackers.gg/crusader-kings/p/2398111a-an-error-occurred-when-launching-the-game-macos>. Steam install on Mac: `~/Library/Application Support/Steam/SteamApps/common/Crusader Kings III/` (same source; the owner's Mac actually has lowercase `steamapps`, §2.9).
- Native Linux: `~/.local/share/Paradox Interactive/Crusader Kings III/logs` per wiki; an older Paradox dev post cites `~/.paradoxinteractive/…`. Unresolved. [wiki + anecdotal] <https://ck3.paradoxwikis.com/Modding>
- Proton: `<steam library>/steamapps/compatdata/1158310/pfx/drive_c/users/steamuser/Documents/Paradox Interactive/Crusader Kings III/logs/`; the Proton build does not read the native path. Steam app id 1158310 confirmed. [anecdotal, community repo] <https://github.com/mekedron/ck3-lowspec-terrain-fix>. Proton prefix layout [official] <https://github.com/ValveSoftware/Proton/wiki/Proton-FAQ>
- `debug.log` also contains engine/startup lines (e.g. mod mount lines), so the tailer must filter on a distinctive marker prefix. [anecdotal] <https://raw.githubusercontent.com/mekedron/ck3-lowspec-terrain-fix/main/tools/check_log.sh>
- `-debug_mode` is a documented launch option; disabled by default; enables console, debug menus, file watcher. The wiki does not say `debug.log` output depends on it. [wiki] <https://ck3.paradoxwikis.com/Debug_mode>
- Existing VOTC project polls `debug.log` (startup checks "CK3 path, debug.log presence/readability, and Iron Man mode"), uses a mod-written heartbeat marker; its installation docs list no launch option. Weak, concept-level evidence only. [official, VOTC] <https://github.com/Voices-of-the-Court/VOTC/releases/tag/v2.0.4>
- The 17MB claim: see C3. <https://github.com/kaiseer1/historical-director-project/issues/1> [anecdotal]
- *Observed on the owner's Mac (2026-10-04; listings and the first lines of the file; no Paradox content stored here):* the user folder is `~/Documents/Paradox Interactive/Crusader Kings III/` and its `logs/` subfolder exists with `debug.log`, `error.log`, `game.log` and others, all last written at the same minute as the latest launch. After roughly one minute of startup with a save loaded, sizes were about 1.5 MB (`debug.log`, ~17k lines), 1.1 MB (`error.log`) and 1.0 MB (`game.log`): a single startup already writes a few MB before the player does anything (a data point for the log-cap question, **not** a measurement of the cap; installed mods unknown). `debug.log` lines start with a bracketed clock time, a level letter and `source-file:line`, then the text; some entries span several lines. Its first lines record `Architecture: AArch64`, so that launch ran natively. Whether that launch used `-debug_mode` is not known. A `console_history.txt` exists in the folder, so the console has been used at some point.

### 2.2 HUD button and scripted GUI
- GUI files live in `game/gui/` (mods mirror with `gui/`); scripted GUIs are `.txt` in `common/scripted_guis/`. [wiki] <https://ck3.paradoxwikis.com/Interface>
- Overriding vanilla windows/types/templates is **first-loaded-wins (FIOS)**; blocks can be changed with `blockoverride`; the wiki says there is no direct hook mechanism for adding to vanilla windows. [wiki] same page.
- **Scripted widgets** (since CK3 1.5): the mod defines a named window in its own `.gui` and registers it in a `.txt` under `gui/scripted_widgets/`; registered windows spawn when the map view loads; no vanilla file override needed. [official] <https://www.paradoxinteractive.com/games/crusader-kings-iii/news/dev-diary-87-royal-modding>. Window example with `layer = top` [wiki] same Interface page.
- A button invokes a scripted GUI via `GetScriptedGui('name').Execute(GuiScope.SetRoot(GetPlayer.MakeScope).End)`; `SetRoot` sets root scope (here the player); `AddScope` adds named scopes. A scripted GUI definition has a `scope`, an `effect` block, optional `is_shown`/`is_valid`, optional confirm texts. [wiki] <https://ck3.paradoxwikis.com/Interface>, <https://ck3.paradoxwikis.com/Data_types>
- UI variable system (`GetVariableSystem`) resets on game restart. GUI dev tooling: `-debug_mode -develop` auto-reloads `.gui`; console `reload gui`, `tweak gui.debug`. [wiki] Interface page.
- `script_docs` writes all effects/triggers/etc. to the `logs` folder; the data-types dump writes `data_types.log` there. Console command `run <file>` reads from the `run` folder. [wiki] <https://ck3.paradoxwikis.com/Console_commands>, <https://ck3.paradoxwikis.com/Data_types>
- VOTC concept (docs only, no code read): a CK3 mod plus a separate desktop app; needs the CK3 user-folder path; clipboard forwarding; incompatible with Ironman "because the mod uses console commands" and with achievements. The community fork README mentions parsing the player ID from game logs; a fork FAQ mentions a missing `run` folder file causing an app error. [official + anecdotal] <https://raw.githubusercontent.com/Voices-of-the-Court/Voices_of_the_Court_Docs/HEAD/installation.md>, <https://raw.githubusercontent.com/Voices-of-the-Court/Voices_of_the_Court_Docs/HEAD/Common%20errors.md>
- VOTC licensing: app GPL-3.0; mod repo CC BY-SA 4.0. [source] <https://raw.githubusercontent.com/Voices-of-the-Court/votc_mod/HEAD/README.md>

### 2.4 SDL3 and Dear ImGui
- Stable: SDL **3.4.18** (2026-10-02); Dear ImGui **v1.92.9b** (2026-07-31). vcpkg master: sdl3 3.4.18, imgui 1.92.9, curl 8.22.0, nlohmann-json 3.12.0. [source] <https://api.github.com/repos/libsdl-org/SDL/releases>, <https://api.github.com/repos/ocornut/imgui/releases>, <https://github.com/microsoft/vcpkg/tree/master/ports>
- Available since SDL 3.2.0: `SDL_WINDOW_BORDERLESS/ALWAYS_ON_TOP/TRANSPARENT/NOT_FOCUSABLE`, `SDL_SetWindowAlwaysOnTop`, `SDL_SetWindowOpacity`, `SDL_SetWindowFocusable`, `SDL_RaiseWindow` (request only, subject to WM policy). `SDL_SetWindowOpacity` is implemented on Windows, macOS, X11 and Wayland. [source] <https://github.com/libsdl-org/SDL/blob/release-3.4.18/include/SDL3/SDL_video.h>
- Always-on-top per OS: macOS `NSFloatingWindowLevel`; Windows topmost; X11 `_NET_WM_STATE_ABOVE`; **Wayland backend has no handler**. SDL does not set `canJoinAllSpaces`/`fullScreenAuxiliary`. [source] <https://github.com/libsdl-org/SDL/blob/release-3.4.18/src/video/wayland/SDL_waylandvideo.c>, <https://github.com/libsdl-org/SDL/blob/main/src/video/cocoa/SDL_cocoawindow.m>
- `SDL_SetWindowShape` makes fully transparent areas click-through (needs `SDL_WINDOW_TRANSPARENT`). Click-through verified in source for macOS only; Windows/X11 not checked. [source] <https://github.com/libsdl-org/SDL/blob/main/include/SDL3/SDL_video.h>
- Transparency implementation: macOS non-opaque window + `CAMetalLayer` non-opaque; Windows `DwmEnableBlurBehindWindow` (upstream FIXME re hybrid GPUs); SDL_Renderer D3D11 and Metal paths handle `SDL_WINDOW_TRANSPARENT` explicitly; D3D12 does not. X11 selects a transparent GL visual. [source] <https://github.com/libsdl-org/SDL/blob/release-3.4.18/src/render/SDL_render.c>
- `SDL_ClaimWindowForGPUDevice()` fails for transparent windows (3.2.30, 3.4.0, 3.4.18); tracked in <https://github.com/libsdl-org/SDL/issues/15181>.
- SDL has **no API to return focus to another application**; platform layer needed. `SDL_WINDOW_NOT_FOCUSABLE` maps to `WS_EX_NOACTIVATE` (Win), WM hint input=False (X11), `canBecomeKeyWindow=NO` (macOS), and cannot receive keyboard focus. [source] <https://github.com/libsdl-org/SDL/blob/main/src/video/windows/SDL_windowswindow.c>

### 2.11 Distribution facts
- **Un-notarized macOS apps:** Apple's documented route is attempt to open → System Settings → Privacy & Security → Open Anyway → Open; right-click → Open no longer works from macOS 15. Apple silicon requires at least an ad-hoc signature (the linker adds it for arm64). <https://support.apple.com/en-us/102445>, <https://eclecticlight.co/2024/08/10/gatekeeper-and-notarization-in-sequoia/>, <https://eclecticlight.co/2020/08/22/apple-silicon-macs-will-require-signed-code/>
- **Notarization requirements:** paid Apple Developer Program, Developer ID Application certificate, hardened runtime, secure timestamp, no `get-task-allow`, `xcrun notarytool submit --wait` with an app-specific password or App Store Connect API key (preferred for CI), then `xcrun stapler staple`. <https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution>
- **VOTC-CE release baseline (concept level):** tag-triggered GitHub Actions matrix on macos-latest + windows-2022 building with Electron Forge, then a release job that publishes a GitHub Release; assets are a Windows Squirrel installer, a macOS arm64-only zip and a dmg with the same unversioned filename on every release (macOS dmg ~247 MB, Windows installer ~260 MB: Electron); no signing/notarization, no Linux artefact, no checksums, no visible test CI, GitHub Issues disabled; the mod ships from a separate repo/version and is mirrored on Steam Workshop, and users must match app and mod versions. <https://github.com/szmania/Voices_of_the_Court/releases>, <https://steamcommunity.com/sharedfiles/filedetails/?id=3654567139>, <https://github.com/szmania/Voices_of_the_Court/pull/14> (Linux/Proton fallback to a plain always-on-top window).
- **vcpkg and builds:** vcpkg's `curl` validates TLS with Schannel on Windows, **Apple SecTrust (the Keychain) on macOS** (the port builds with `USE_APPLE_SECTRUST` on Apple platforms) and **OpenSSL on Linux with `--openssldir=/etc/ssl`**, so Debian/Ubuntu/Fedora default paths normally work; our earlier assumption that macOS OpenSSL had no system trust was wrong (see §2.15). Built-in triplets: `arm64-osx`, `x64-linux`, `x64-windows-static` etc.; `x64-osx` is a community triplet. Dependencies link statically (SDL3's dynamic API still allows `SDL3_DYNAMIC_API` override). <https://raw.githubusercontent.com/microsoft/vcpkg/master/ports/curl/vcpkg.json>, <https://api.github.com/repos/microsoft/vcpkg/contents/triplets>, <https://github.com/libsdl-org/SDL/blob/main/docs/README-dynapi.md>, <https://curl.se/docs/caextract.html>
- **Runners (queried 2026-10-04):** `ubuntu-latest` = Ubuntu 24.04 (Xvfb, CMake 3.31, Clang 16–18 preinstalled), `macos-latest` = macOS 26 arm64, `windows-latest` = Windows Server 2025; `macos-15-intel` is the last Intel image. <https://docs.github.com/en/actions/reference/runners/github-hosted-runners>, <https://endoflife.date/github-actions-runner-images>
- **AppImage:** type-2 runtime embeds FUSE (no `libfuse2` needed on the user's machine); `--appimage-extract-and-run` works in containers; build on the oldest distro you support. <https://github.com/AppImage/AppImageKit/wiki/FUSE>, <https://github.com/AppImage/type2-runtime>
